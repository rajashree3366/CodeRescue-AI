IBM Bob Rescue Center

Investigate → Analyze → Plan → Rescue → Test → Review

Bob is the AI-assisted engineering layer of this rescue: it inspects the real ShopSphere source, classifies findings, plans remediation, drafts documentation, generates real reviewable patches, then actually executes a set of assertions against the loaded modules — no test result or patch outcome shown here is claimed without running.

Integration boundary — read this first.
What real IBM Bob is: an IDE-embedded AI development partner (bob.ibm.com) that works inside a developer's own editor/codebase.
What's actually running here: this prototype has no official Bob API, SDK, CLI, or MCP connector available in this sandboxed environment — we checked the connector registry and found none — and no credentials were available or invented. So the workflow below is a locally-implemented engineering pipeline that performs real operations against the real ShopSphere source embedded in this page: it parses require() calls, classifies findings from actual code patterns, generates full-file patches, computes a genuine line-by-line diff, reloads the patched module, and re-executes the same assertions — all in your browser, nothing scripted or faked.
Where a real Bob connection would go: the loadAllModules(), patch-generation, and runTestHarness() functions are the integration boundary — in a live deployment these would call Bob's actual API/CLI (once an endpoint and credentials are configured) instead of this local analyzer, while the rest of this UI stays the same.
